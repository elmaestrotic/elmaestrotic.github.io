Algoritmos de Ordenamiento: Merge Sort, Quick Sort y Heap Sort

Una guía completa sobre su funcionamiento, complejidad y comparación.

Introducción

Los algoritmos de ordenamiento son fundamentales en la informática para organizar datos de manera eficiente. En esta página, exploraremos tres algoritmos populares: Merge Sort, Quick Sort y Heap Sort. Cada uno tiene sus fortalezas y se basa en diferentes principios. Analizaremos su funcionamiento, complejidad algorítmica y los compararemos entre sí.

Merge Sort

Merge Sort es un algoritmo de ordenamiento basado en el paradigma de "divide y conquista". Divide el arreglo en mitades recursivamente hasta que cada subarreglo tenga un solo elemento, y luego fusiona (merge) estos subarreglos de manera ordenada.

Funcionamiento

  1. Divide el arreglo en dos mitades.
  2. Ordena recursivamente cada mitad.
  3. Fusiona las dos mitades ordenadas en un solo arreglo ordenado.

Ejemplo: Para un arreglo [38, 27, 43, 3, 9, 82, 10], se divide en [38, 27, 43] y [3, 9, 82, 10], y así sucesivamente hasta fusionar todo ordenado.

Complejidad Algorítmica

  • Mejor caso: O(n log n)
  • Caso promedio: O(n log n)
  • Peor caso: O(n log n)
  • Espacio: O(n) (no es in-place)

Es estable y predecible, ideal para grandes conjuntos de datos.

Quick Sort

Quick Sort también sigue "divide y conquista". Selecciona un elemento pivote y particiona el arreglo en dos subarreglos: uno con elementos menores al pivote y otro con mayores. Luego, ordena recursivamente los subarreglos.

Funcionamiento

  1. Elige un pivote (por ejemplo, el último elemento).
  2. Particiona el arreglo moviendo elementos menores a la izquierda y mayores a la derecha.
  3. Recursivamente aplica Quick Sort a los subarreglos.

Ejemplo: Para [38, 27, 43, 3, 9, 82, 10], si pivote es 10, particiona en menores y mayores, y recursa.

Complejidad Algorítmica

  • Mejor caso: O(n log n)
  • Caso promedio: O(n log n)
  • Peor caso: O(n²) (cuando el pivote es siempre el menor/mayor)
  • Espacio: O(log n) (in-place, pero recursión usa pila)

No es estable, pero es eficiente en la práctica con buena elección de pivote.

Diagrama simplificado de Quick Sort (partición).

Heap Sort

Heap Sort utiliza una estructura de datos llamada heap (montículo binario). Primero construye un max-heap del arreglo, luego extrae repetidamente el elemento máximo y ajusta el heap.

Funcionamiento

  1. Construye un max-heap del arreglo.
  2. Intercambia el raíz (máximo) con el último elemento y reduce el tamaño del heap.
  3. Ajusta el heap (heapify) y repite hasta ordenar todo.

Ejemplo: Para [38, 27, 43, 3, 9, 82, 10], se construye el heap y se extraen máximos.

Complejidad Algorítmica

  • Mejor caso: O(n log n)
  • Caso promedio: O(n log n)
  • Peor caso: O(n log n)
  • Espacio: O(1) (in-place)

No es estable, pero garantiza O(n log n) en peor caso y es in-place.

Comparación entre los Algoritmos

Aquí una tabla comparativa para resaltar las diferencias clave:

Algoritmo Mejor Caso Caso Promedio Peor Caso Espacio Estable In-Place
Merge Sort O(n log n) O(n log n) O(n log n) O(n) Sí No
Quick Sort O(n log n) O(n log n) O(n²) O(log n) No Sí
Heap Sort O(n log n) O(n log n) O(n log n) O(1) No Sí

Resumen: Merge Sort es ideal cuando se necesita estabilidad y predictibilidad, pero usa más espacio. Quick Sort es rápido en promedio y eficiente en espacio, pero puede degradarse en peor caso. Heap Sort ofrece garantías en peor caso y es in-place, pero no es estable. La elección depende del contexto: para datos grandes y estables, Merge; para eficiencia general, Quick; para garantías sin espacio extra, Heap.
